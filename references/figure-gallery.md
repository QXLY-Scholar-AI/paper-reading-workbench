# 论文图表画廊 v1

## 必须先精读，再重绘

先充分阅读全文或复用已有精读；针对每张图回读图注、引用该图的前后文、方法和数据说明。仅请求插图分析时可保存内部阅读记录，不要求额外交付五步正文。多次精读可复用，但必须核对论文版本和图号。不得只看截图按外形选图型。记录物理页码和实际原文节选，解释图中变量、单位、统计量、误差线、样本、分组与结论。数据缺失时语境仍是必需输入。

脚本不调用模型；宿主AI负责精读、识图、检索数据、编写和审查R。自动候选不是已识别正确的图，必须目视确认边框、坐标、图例、子图和图注，必要时修改bbox重新扫描。扫描PDF无文字时明确OCR缺口。第一版面向文字型PDF，复杂跨页/无图注布局可能需要人工框选，不保证全检出。

## 每张图的三段结构（固定栏目，逐图撰写内容）

1. **插图解析**（interpretation）：从全文语境解释这张图在回答什么问题；逐一说清子图、比较对象、横纵轴、单位、统计量、样本、分组和区间含义，连接作者结论与可支持的解释。保留关键限定，例如描述相关不等于因果、基期不等于估计零、图注与图像的差异。不是只报图型，也不能把全文摘要贴到每张图。
2. **数据来源**（data.source及sources）：区分论文的数据来源和本次实际绘图输入；写明所用年份/样本及处理状态、链接与核验时间、是否下载、是否完成字段/图对应验证。数字化、正文汇总、模拟示意和真实原数据分别说明；具体误差可链接详细文件。入口存在不能写已取得数据，运行成功不能写精确复现。
3. **研究应用建议**（reuse）：以专业方法视角，针对这一张图说明：适合哪类研究问题/情景；需要什么数据结构、变量与观测单位；怎样安排分组、轴、统计量和图层以回答问题；给出一个贴合该图的迁移示例；指出最关键的适用限制或误用。建议应足够具体，让用户能判断自己的材料是否适用并知道如何准备数据。作者事实与迁移建议分开，不假定用户已有某领域数据。不要求机械列五个小标题，以连贯的中文段落表达。

禁止将“替换CSV、先读data-mapping.md、核对定义”作为第三段的主要内容，也不能把同一段通用模板复制到每张图。文件操作属于补充说明，不能替代研究方法建议。不同子图若功能不同，分别说明用途。例如分布图讨论样本内归一化与箱宽，事件研究图讨论面板结构、基期、估计量与置信区间，不给所有图套同一条统计注意事项。

## 精读与画廊的三种结果状态

- 仅完成精读：原文插图可点击，但提示“请先完成插图分析”，不生成虚假画廊。
- 仅完成插图分析：画廊页码/引文链接打开同款原文阅读窗口，隐藏精读内容，仅显示插图语境标注；有页码可跳页，唯一定位成功才高亮。
- 两项均完成：精读原图点击跳到gallery.html#figure=图号并打开对应详情；画廊引文跳回阅读页的页码与批注。联动必须按同一PDF指纹验证，不串文献。

两项都未完成不需要结果入口或额外状态页。原文阅读窗口不计作已完成精读，不填造五步正文。旧版结果保留，通过新版本添加联动。复用现有精读时保留其正文，只增加插图相关定位。source-reader-report.json记录引句定位结果。

完成当前任务后检查该PDF是否已有另一种成果。如果两项已齐全，用真实reading.json与gallery.json生成同版联动结果再入库，不能只因一份新精读生成时没有传gallery而误报尚未分析插图。从旧成果恢复清单时，将代码/数据/截图路径指向实际存在的快照文件后再生成；不要假设旧清单中的原工作路径仍然可用。未能恢复已有画廊材料时保留其旧入口并说明具体缺口，不虚构可跳转图号。

## 工作流

1. `python scripts/figure_gallery.py scan --pdf paper.pdf --out gallery-work`。输出候选图、原页、附近段落和数据线索到candidates.json，不覆盖人工整理的gallery.json。
2. 读取每张候选图和完整论文；先生成/读取真实阅读记录或已有reading.json与paper-card.md，再写gallery.json。`reading_record`指向真实存在的阅读记录，paper_sha256必须匹配。每图必须有非空`context`、`interpretation`、`data`、`mode`、`reviewed`及经审查的R文件。
3. 查正文数据声明、补充材料和作者代码，必要时访问官方仓库。逐项登记URL、访问日期、是否已下载、文件/版本、图对应的筛选与统计。数据库存在不等于数据已取得；不绕过申请、登录、付费或访问限制。无法映射字段时只交明确未验证的适配代码，不能称已复现。
4. 数据优先顺序：已取得且映射验证的原数据；正文/图表报告的数值；可校准的图像数字化数据；明确标注的模拟数据模板。`mode`分别为raw_data、reported_values、digitized、template；不将模式当作质量分数。`data.status`如access_required说明数据库需申请，独立于本次重绘数据模式。
5. 运行前宿主检查R代码，不执行下载的未知脚本。`python scripts/figure_gallery.py build --manifest gallery-work/gallery.json --out result --rscript /path/to/Rscript`。脚本不自动安装R依赖、不联网取数据；运行在每图隔离目录，限制180秒。R脚本相对自身目录读写，产生preview.png和redraw.pdf。代码运行失败保留日志和失败状态，禁止放示例预览冒充成功。尚无R环境时不带--rscript，显示未运行。
6. 打开gallery.html核对原图与重绘、研究含义、状态、筛选、收藏和下载。保存运行报告。实际取得的原始数据只按其许可交付；生成自包含HTML会嵌入原图和清单里声明的CSV，避免打包受限或敏感微观数据。

本机R路径可先查Skill目录local-runtime.json（若存在），再查PATH。配置文件不是可移植依赖；迁移时重新定位R。它包含本机路径，不发布到公共仓库。

## gallery.json 格式

schema为paper-figure-gallery/v1；paper包含title、doi、source_pdf、sha256；reading_record为本次或已有精读文件绝对路径；figures为数组。每图包含id（F1等安全标识）、label、page（物理页）、bbox、crop（图片路径）、caption、chart_type、context（page、quote、role对象数组）、interpretation、mode、reviewed（视觉和语义已复核）、data（status、source、sources数组）、r_script、files（需同目录交付的数据文件）、reuse（换数据时的说明）。所有相对路径以清单目录为基准，构建时复制到每图独立目录。R代码审查由宿主负责，reviewed不是安全沙箱。

## 特殊图型

森林图优先使用已报告HR/OR和CI，不以事件比例反算Cox HR；确认横轴线性/对数，截断区间画箭头，不用CI反推精确交互检验。KM曲线需要时间、事件和删失数据；风险集数量不能当存活概率。无个体数据时只生成醒目标注模拟的模板，不以汇总事件数反推真实KM。流程图保留每个已报告节点，缺失节点明确标注，不能静默删除不方便的分支。示意图/医学照片等可收藏解读，R不适合精确重绘时明确说明。
