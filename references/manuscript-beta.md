# 论文初稿（Beta）· 以核心文献启动写作项目

用户说“以这些精读文献为核心，结合补充文献，围绕课题××写一篇论文初稿”时启用。先读包内 [中文学术写作](../modules/academic-writing-zh/SKILL.md)，以及其中的 evidence-and-analysis.md、manuscript-writing.md 和 research-design.md。先判断课题与现有材料是否匹配，再决定能否进入写作；用户给出的课题是待评估的方向。规则已随包附带，不要求另装 Skill。

## 入口语义与逐步推进（现行流程）

网页“论文初稿（Beta）：未生成”只复制一条启动指令，锚定当前论文为核心材料之一，不能将一篇文献自动视为足以写完整论文。后续研究与写作在Codex聊天中推进，网页主要用于对照稿件、文献依据和后续评审意见。判断材料是否足够看证据与研究设计，不设凑篇数的门槛。

1. **建立项目、清点材料**：记录核心PDF指纹、已有精读/图/参考文献，以及用户自己的研究、数据和草稿。保存writing-progress.md，状态为“选题与材料梳理”；启动不等于初稿已生成。
2. **明确主题与研究问题**：按research-design.md讨论研究对象、具体问题、范围、稿件类型、目标读者与预期贡献。用户给了主题仍须结合证据评估；只给方向就共同收敛课题。若仍是【填写课题】，先提醒“请填写课题！”，可以请用户提供研究方向进入选题讨论，不自行猜题或直接起草。
3. **补充证据与可行性**：按evidence-and-analysis.md检查相关与相反文献、方法和数据可用性，形成材料账本与feasibility.md。确定哪些章节已有依据、哪些需要补材料。来源不切题不能为了成稿硬纳入。
4. **讨论论证大纲**：按manuscript-writing.md提出章节及各节要回答的问题、主要论据、来源id和拟用图表。主题/研究问题与大纲是实际讨论节点，应由用户确认或修改后进入对应写作，不以“默认通过”跳过；已有明确确认的内容不重复问。用户在当前会话已提供并认可的主题/提纲可复用，不能以流程为由重新做一遍。
5. **按确认范围起草**：依据已定大纲逐节或按用户明确授权的整稿范围写作；持续保留出处，区分他人结果与自己的研究。材料缺口不虚构填补，更新writing-progress.md的已完成、待补和修改决定。
6. **评审与修订**：按revision-and-submission.md及用户需要检查论证、证据、结构和表述，再按意见修订。评审意见与稿件事实分开，不能把“建议补分析”写成已经做过。产出真实稿件后才渲染和入库；中途选题/大纲记录仅保存项目文件，不把它们登记为已完成的初稿。

用户明确授权省略已完成步骤或一次交整稿时可按授权推进，但必须确认必要的主题、设计、结构和证据已有材料支持，不能用一条通用提示词代替完整工作流程。

网页边界：稿件中的来源id应能对应材料账本和文献位置，便于对照阅读。评审建议与用户勾画在网页展示是可行扩展，但需绑定稿件版本、段落/引句锚点，区分AI建议和用户批注，标明待处理/已处理并支持导出；正文修订后重新定位，无法定位的标为待核对，不自动套用旧坐标。目前不应声称已经完成了稿件评审勾画界面。

## 材料与任务

1. 从 library.json 取得用户选择的核心论文及最新精读、证据、画廊；回读原文，不能只使用精读摘要。用户可以提供更多PDF、题录、DOI、链接，也可以指定参考文献结果页中的条目编号。不要默认把所有参考文献都加入。
2. 课题缺失、为空或仍为“【填写课题】”“填写课题”等模板占位文字时，必须明确回复“请填写课题！”，等待用户补充主题或研究方向后进入选题讨论；不能把占位文字当作研究主题，也不能自行猜题。在研究问题与大纲明确并经用户讨论确认前不进入正文起草。篇幅未指定可用中文约5000字作为工作假设并告知。指定实证稿但没有自己的数据时先说明缺口，询问采用综述还是研究方案；明确要求综述时直接写作。不得把引用论文的实验写成用户已完成的研究。
3. 对补充文献逐项核对身份并检索材料。优先获取合法全文，其次真实摘要、作者或出版社简介。只有题名/作者/出处也应保留，标为 metadata；题名可以提示可能相关性，不能据此写研究方法或结果。有简介不等于有摘要，获取不到时如实登记。正文中的“有研究发现”必须有已读内容支持。
4. 材料账本记录 id、完整题录 citation、level（full_text/abstract/introduction/metadata）、locator（已读页码/段落或实际来源URL）、note（材料范围及局限）、verified（身份已核对）。全文不代表一切细节均已核验。摘要材料只支持摘要明确报告的内容，不能补造未见统计量或局限。记录跨文献结论冲突。

## 写作前的课题可行性判断（必做）

在取得真实课题、读过核心论文和补充文献的可读材料后，先写入 feasibility.md，并在聊天简要告知判断。不能仅凭题名匹配或参考文献数量认定可写，也不能因为文章难获取就断言课题本身不可行。

- 对照课题的研究对象、问题、范围和预期稿件类型，说明核心及补充文献分别支撑什么；引出来源id和已读位置，区分直接证据、间接背景、相反证据和不相关材料。
- 检查是否已有足够依据组织论证与主要章节，数据/方法能否回答研究问题，有哪些关键证据缺口或结论冲突。基于当前材料指出可能贡献，不能未经检索宣称“首次”或已证明创新。
- 区分“该方向有研究价值”和“现有材料足够写这类初稿”。几篇背景论文不能代替用户自己的实证数据，只有简介或题录不能支撑完整结果部分；也不设机械的最低文献篇数。
- 给出结论：①现有材料可支持——说明可写的类型与边界，进入论证大纲讨论，已确认大纲时继续起草；②调整范围或补关键材料后可支持——提出最小调整、理由及待补项，若调整课题/研究问题/稿件类型，先征求用户确认，等待答复后再写；③当前材料不足以判断或支撑——明确具体缺口，只交评估与可行方向，不强行生成完整稿。

不要擅自替换用户题目，也不要为了凑成论文而预设结论或虚构研究。作者明确要求继续做受限初稿时，按获授权范围推进，保留相应边界与待补标记。

## 写作与图

围绕问题综合论证，完整交付标题、摘要、关键词、引言、文献分析、方法/材料说明、结果/综合发现、讨论、结论和参考文献。综述的方法只写实际完成的选材过程，不虚构系统检索与PRISMA；方案的预期结果明确标为预期。缺少必要研究数据时给出有依据的段落与醒目待补说明，不能用空白模板冒充完整论文。

每段的实质判断标出来源id；在结构化稿件中用 citations 与 locator 追踪，正文引用格式为 [S1]。只保留实际引用的参考文献；metadata条目放在材料账本的待补列表，不作为实质结论依据。每一来源的具体论述仍由宿主AI对照原材料复核，脚本仅检查结构与引用关系。

画廊素材是候选。确认图义、数据、复用条件后优先以R重绘合适的综述比较图或证据框架图。模拟曲线不能包装成研究结果；原论文截图不能当作本研究原创图。图注说明来源、改绘方式与数据性质；无法确认复用条件就链接画廊，不强行插入。不要为“带图”制造数据。

## 保存与交付

宿主AI完成写作后填写 draft.json，运行 scripts/manuscript_draft.py --card draft.json --out 新成果目录，生成 manuscript.md、manuscript.html、draft-report.json 与 sources.json，并将 feasibility.md 一并放入成果目录保存。以首篇核心PDF作为归档锚点，其他核心PDF指纹存于 core_papers；使用 paper_library.py register 入库。多个课题/修订稿均增加版本。打开网页，交付 Markdown 下载、材料账本、待补项与图的来源。网页不调用模型。

draft.json 结构：schema=paper-manuscript/v1；source_sha256=归档PDF的64位SHA256；title、topic、kind（review/proposal/empirical）；core_papers=[SHA256,...]；keywords=[词,...]；sources=[{id,citation,level,locator,note,verified:true}]；sections=[{id,title,paragraphs:[{text,citations:[来源id,...],locator:"证据位置或分析说明"}]}]，id需覆盖 abstract/introduction/literature/methods/results/discussion/conclusion；figures可选=[{file:"images/图.png",caption,source_ids:[来源id,...]}]，相对于draft.json，脚本复制进成果包；gaps=[待补项,...]。empirical额外要求 user_data={provided:true,description,locator}，只在实际已提供数据时填写。

beta 当前验证范围：保存、引用关联、材料分级、图像打包和论文库版本保留。没有指定课题前不生成假论文；科学内容质量需要真实课题试写后复核。
